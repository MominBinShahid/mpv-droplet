# mpv-droplet

A tiny AppleScript droplet that builds `/Applications/mpv.app` so Finder can open videos in Homebrew's mpv.

## Why I built this

I had a 4K WEB-DL movie whose colours came out green and purple in VLC and IINA.
`ffprobe` showed it was Dolby Vision Profile 5 (`dv_profile=5`,
`dv_bl_signal_compatibility_id=0`). Profile 5 stores the picture in Dolby's IPT
colour space with no HDR10 fallback, so a player that ignores the Dolby Vision
metadata shows it green and purple.

mpv's `gpu-next` renderer (libplacebo) applies the Dolby Vision reshaping and
played it correctly. The problem was getting Finder to use it:

- Homebrew's `mpv` formula is command-line only. There's no `.app`, so Finder
  can't offer it in "Open with".
- The official `mpv.app` from mpv's GitHub releases is only ad-hoc signed and
  not notarized, so Gatekeeper blocks it.
- Homebrew can't ship it as a cask either: since Homebrew 5.0 casks must pass
  Gatekeeper, and the `stolendata-mpv` cask (a third-party build) was disabled on
  2026-09-01 for exactly that reason.

So I wrote a tiny droplet that I build locally (no Gatekeeper prompt) and that
hands files to Homebrew's mpv.

## Requirements

- macOS
- [Homebrew](https://brew.sh)
- mpv: `brew install mpv`
- Xcode Command Line Tools, for `make` and `swift`: `xcode-select --install`

## Install

```
git clone https://github.com/MominBinShahid/mpv-droplet.git
cd mpv-droplet
make
```

This builds `/Applications/mpv.app` with the mpv icon. To make it the default
player, select a video (e.g. a `.mkv`) in Finder, press `Cmd+I`, pick **mpv**
under "Open with" and click **Change All…**. Repeat for `.mp4` and any other
types you use.

## Recommended mpv.conf

mpv reads its settings from `~/.config/mpv/mpv.conf`:

```
vo=gpu-next     # renderer that handles Dolby Vision (incl. Profile 5) and HDR
alang=eng,en    # audio language priority
slang=eng,en    # subtitle language priority
```

`vo=gpu-next` is already the default on recent mpv; pinning it is harmless and
keeps the behaviour if the default ever changes. The `alang`/`slang` lines are
an example: list whatever language codes you want, in order of preference.

## Files

| File | What it is |
|---|---|
| `mpv-droplet.applescript` | The app's code |
| `Makefile` | Automates the build (all steps below); run `make` in this folder |
| `svg2png.swift` | Helper that renders mpv's SVG logo to PNG at a given size |
| `build/` | Generated by `make` (icon PNGs, `mpv.icns` and the staged `mpv.app`); `make clean` deletes it |

## How the code works

- `on open theFiles` runs when files are opened with the app (Finder "Open with",
  or dragging onto the icon). It quotes each path and starts mpv in the
  background (`&`), so the droplet exits right away.
- `on run` runs when the app is opened with no file. It shows an empty mpv
  window you can drag videos onto.
- `--player-operation-mode=pseudo-gui` makes mpv behave like a normal app:
  it keeps its window open and doesn't need a Terminal. It still reads `mpv.conf`.

## Quick build: `make`

Run these from the repo folder:

| Command | What it does |
|---|---|
| `make` | Builds `/Applications/mpv.app` with the mpv icon |
| `make open` | Builds if needed, then opens the app |
| `make check` | Verifies the signature and shows which files the app accepts |
| `make icon` | Builds only the icon (`build/mpv.icns`) |
| `make clean` | Deletes `build/` |
| `make uninstall` | Deletes `/Applications/mpv.app` |

make compares file timestamps and only redoes what changed. Edit the
`.applescript` and `make` recompiles the app but reuses the icon. Run `make`
twice with no changes and it prints "Nothing to be done".

`make` builds and signs the app in `build/mpv.app` first and only replaces
`/Applications/mpv.app` once that succeeds, so a script with a compile error
leaves your installed app alone. If Homebrew or mpv is missing, it stops and
tells you what to install.

## Building by hand, step by step

### 1. Compile it into an app

```
osacompile -o /Applications/mpv.app mpv-droplet.applescript
```

`osacompile` is the AppleScript compiler that ships with macOS. When the `-o`
name ends in `.app`, it builds a full app bundle instead of a bare script.
What it creates (abridged; the real bundle also has `PkgInfo`, `droplet.rsrc`
and, once signed, `_CodeSignature`):

```
mpv.app/
└── Contents/
    ├── Info.plist                    ← app metadata (name, which files it accepts)
    ├── MacOS/droplet                 ← Apple's ready-made launcher program
    └── Resources/
        ├── Scripts/main.scpt         ← your script, compiled
        └── droplet.icns              ← the app icon
```

### 2. Why it shows up in "Open with"

Because the script has an `on open` handler, `osacompile` builds a *droplet*:
an app that accepts files. It writes this into `Info.plist` automatically:

```
CFBundleDocumentTypes → extensions: *   (any file), role: Viewer
```

That entry is what tells Finder "this app can open files". Without `on open`,
the app would only run, and Finder would never offer it for files. Check it:

```
plutil -p /Applications/mpv.app/Contents/Info.plist
```

### 3. Give it the mpv icon (optional)

Without this step the app has the generic AppleScript droplet icon.

```
SVG="$(brew --prefix)/opt/mpv/share/icons/hicolor/scalable/apps/mpv.svg"

# render the logo at every size macOS wants, then pack them into an .icns
mkdir -p build/mpv.iconset
for s in 16 32 128 256 512; do
  swift svg2png.swift "$SVG" "build/mpv.iconset/icon_${s}x${s}.png" $s
  swift svg2png.swift "$SVG" "build/mpv.iconset/icon_${s}x${s}@2x.png" $((s * 2))
done
iconutil -c icns build/mpv.iconset -o build/mpv.icns

# replace the droplet icon; remove the asset catalog that newer macOS prefers over it
cp build/mpv.icns /Applications/mpv.app/Contents/Resources/droplet.icns
rm -f /Applications/mpv.app/Contents/Resources/Assets.car
/usr/libexec/PlistBuddy -c 'Delete :CFBundleIconName' /Applications/mpv.app/Contents/Info.plist

# changing files inside the app breaks its signature, so re-sign it (ad-hoc, local use)
codesign --force --deep --sign - /Applications/mpv.app
touch /Applications/mpv.app
```

### 4. Tell macOS about the app (optional)

```
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister -f /Applications/mpv.app
```

LaunchServices is macOS's database of which app opens which file types. Finder
finds new apps on its own eventually; this makes it happen immediately.

### 5. Make it the default for a file type

Select a `.mkv` file in Finder → `Cmd+I` → "Open with" → **mpv** → **Change All…**.
Repeat for `.mp4` etc.

### 6. Changing it later

Edit the `.applescript` file, then run `make` (or step 1 by hand). Your
"Open with" setting is kept because the app's name and location stay the same.

## Other route: Script Editor (no Terminal)

1. Open `mpv-droplet.applescript` in **Script Editor**.
2. **File → Export…**, set **File Format: Application**, and save it as `mpv`
   in `/Applications`.

The result is the same as step 1 (it still needs step 3 for the mpv icon).

## Notes

- The app finds mpv in `/opt/homebrew/bin` (Apple Silicon) or `/usr/local/bin`
  (Intel). `brew upgrade mpv` keeps those paths.
- The app is named `mpv.app` because that name is what Finder shows in
  "Open with".
- macOS places round icons on a light grey rounded square. That's normal.
